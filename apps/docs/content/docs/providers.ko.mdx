Multica는 31개 AI 코딩 도구를 지원합니다. 사용 중인 도구를 대체하지는 않습니다. 런타임이 컴퓨터에 이미 설치되어 로그인된 도구를 호출하고 실행 진행 상황과 결과를 태스크에 기록합니다. 이미 사용 중인 도구가 있다면 보통 그대로 쓰면 됩니다. 아직 정하지 않았다면 다음 네 가지를 보세요.

에이전트를 생성할 때 도구를 고르는 방법은 [에이전트 생성 및 구성](/agents-create)을 참고하세요.

- 컴퓨터에 이미 설치되어 있는가
- 계정에서 어떤 모델을 사용할 수 있는가
- Multica가 MCP를 설정해야 하는가
- 팀에서 어떤 스킬을 재사용해야 하는가

설치 방법은 [AI 코딩 도구 설치](/install-agent-runtime)를 참고하세요.

## 각 도구의 용도

Google에서 제공합니다. CLI 바이너리 이름은 `agy`입니다. Google의 Antigravity 서비스와 연동되며 Gemini 기반의 기본 모델을 함께 제공합니다. **세션 재개가 동작합니다** — `--conversation <id>`를 통해서이며, stdout이 구조화된 이벤트 스트림이 아니라 일반 텍스트이기 때문에 데몬이 CLI의 로그 파일에서 conversation UUID를 캡처합니다. **모델 선택이 동작합니다** — `--model` flag(agy 1.0.6에서 추가)를 통해서이며, 데몬이 `agy models`로 카탈로그를 열거하고 선택된 값을 그대로 전달합니다. 이 값들은 `provider/model` slug가 아니라 `Claude Opus 4.6 (Thinking)` 같은 사람이 읽는 표시 이름이라는 점에 유의하세요. 또한 agy는 인식할 수 없는 값을 받으면 조용히 빈 실행을 하므로, 직접 입력하기보다 발견된 목록에서 선택하는 것을 권장합니다. 스킬은 `.agents/skills/`에 들어갑니다(CLI가 Gemini CLI의 워크스페이스 스킬 레이아웃을 그대로 따릅니다 — [Antigravity 마이그레이션 문서](https://antigravity.google/docs/gcli-migration) 참고).

Claude Code에서 데몬 환경 변수 `CLAUDE_CONFIG_DIR`에 절대 경로를 지정하면 Multica는 해당 위치에서 사용자 및 플러그인 스킬을 조회하고 가져옵니다. 시작 래퍼 내부에서만 설정한 경로는 스캐너에 반영되지 않습니다.

Amp의 모델 필드는 기반 모델 ID가 아니라 `high` 같은 Amp **모드**를 선택합니다. 비워 두면 Amp의 기본값을 사용합니다.

Amp는 데몬 또는 에이전트 환경에 `AMP_API_KEY`도 필요하며, 저장된 대화형 로그인만으로는 실행할 수 없습니다.

"Multica의 MCP 관리"는 에이전트 설정에 MCP server를 입력하면 Multica가 실행 전에 해당 도구로 전달할 수 있다는 뜻입니다. 이 열은 Multica가 대신 설정할 수 있는지만 나타내며, 도구 자체에 다른 MCP 설정 방법이 있는지와는 관계없습니다.

"Multica에서 모델 선택"이 —인 도구는 도구 자체 설정에서 모델을 고릅니다. [모델 출처](#모델-출처)를 참고하세요.

### Claude Code

Anthropic에서 제공합니다. **신규 사용자에게 첫 번째 선택지**이며, 가장 완전한 기능 세트를 갖추고 있습니다: 세션 재개가 실제로 동작하고, MCP 구성을 읽으며, `--max-turns`와 `--append-system-prompt` 같은 세부 조정 flag를 지원합니다. Anthropic API 키가 필요합니다.

## 도구 연결

표의 모든 도구는 같은 방식으로 연결됩니다. 컴퓨터의 Multica 데몬이 `PATH`에서 각 도구의 명령을 찾고, 찾은 도구마다 런타임을 하나씩 등록합니다. 실행은 그 컴퓨터에서 도구 자체의 로그인과 구독으로 이루어집니다. Multica는 도구를 함께 배포하지 않으며 모델 호출을 대신 중계하지도 않습니다.

1. 도구의 문서에 따라 설치하고 로그인합니다.
2. 같은 컴퓨터에서 [Multica 데스크톱 앱](/desktop-app)을 열면 컴퓨터가 자동으로 연결됩니다. 또는 CLI를 설치하고 데몬을 시작합니다.

   ```bash
   curl -fsSL https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.sh | bash
   multica setup
   ```

   Windows에서는 첫 줄을 `irm https://raw.githubusercontent.com/multica-ai/multica/main/scripts/install.ps1 | iex`로 바꿉니다. 자체 호스팅 인스턴스는 [자체 호스팅 빠른 시작](/self-host-quickstart)의 명령을 사용합니다.
3. **런타임** 페이지에서 그 컴퓨터 아래에 도구가 나타나는지 확인합니다. `multica runtime list`로도 확인할 수 있습니다. 나중에 다른 도구를 설치했다면 `multica daemon restart`를 실행하거나 데스크톱 앱을 다시 엽니다.
4. 그 런타임에서 [에이전트를 만들고](/agents-create) 태스크를 할당합니다.

데몬의 `PATH`가 닿지 않는 위치에 도구를 설치했다면 `MULTICA_<PREFIX>_PATH`로 그 위치를 지정합니다. [환경 변수](/environment-variables#데몬-설정)를 참고하세요. 컴퓨터 한 대에 여러 도구를 둘 수 있고 워크스페이스 하나에 여러 컴퓨터를 연결할 수 있으므로, 같은 보드에서 한 컴퓨터는 Claude Code를, 다른 컴퓨터는 Codex나 Kimi를 실행할 수 있습니다.

## 끼어들기 지원

다음 실행을 기다리지 않고 [작업 중인 실행에 메시지를 추가](/mentioning-agents#실행-중인-에이전트에게-끼어들기)할 수 있습니다. AI 코딩 도구가 이를 지원해야 하며, 다음 버전 이상이어야 합니다.

| 도구 | 최소 버전 |
|---|---|
| Antigravity | 1.4.8 |
| Claude Code | 2.1.110 |
| Codex | 0.100.0 |
| Cursor Agent | 2026.10.14 |
| Grok | 1.0.14 |
| Hermes | 0.22.3 |
| Kiro CLI | 2.33.0 |
| Pi | 1.4.0 |

그 밖의 도구나 이전 버전에서는 '현재 실행에 추가'가 나오지 않습니다. 답장은 현재 실행이 끝난 뒤 새 실행에서 처리되거나, 현재 실행을 중지하고 다시 시작하게 됩니다.

## 모델 출처

모델을 선택하지 않으면 Multica가 해당 도구의 기본 설정을 사용합니다. 목록이 비어 있다면 런타임이 온라인이고 도구에 로그인되어 있는지 확인한 뒤 모델 목록을 새로 고치세요.

Devin은 로컬 ACP로 실행되며 stdio MCP를 지원합니다. HTTP/SSE는 CLI가 지원을 선언한 경우에만 전달됩니다. skill 가져오기는 Devin/Cognition 디렉터리 다음에 `~/.codeium/<channel>/skills`(`windsurf`, `windsurf-next`, `windsurf-insiders` 순), 마지막으로 `~/.agents/skills`를 검색합니다.

Devin 모델 목록에는 계정에서 사용할 수 없는 모델도 포함될 수 있습니다. 전체 모델 ID, 명확한 세션 모델 이름 또는 카탈로그의 계열 slug/별칭(예: `opus`)을 선택하거나 비워 두어 CLI 기본 모델을 사용하세요. Multica는 전송 전에 실제 모델을 확인하고 다른 계열로의 대체를 거부합니다. 모호한 이름, 임의의 부분 이름, 사용할 수 없는 변형은 전체 ID로 지정하세요. 사용량은 반환된 모델에 귀속되며 Adaptive는 라우팅 ID로 기록합니다. 하위 모델은 추측하지 않습니다.

Devin은 `WINDSURF_API_KEY`가 있으면 사용하고, 없으면 `devin auth login`으로 저장한 인증 정보를 사용합니다. 알 수 없는 ACP 인증 방식도 저장된 로그인을 막지 않습니다. Multica는 권한을 높이지 않고 설정된 세션 모드를 유지합니다. 기본값이 `plan`이면 파일을 수정하는 태스크를 보내기 전에 Devin에서 편집 가능한 모드로 바꾸세요.

에이전트를 만들 때 모델 목록은 해당 런타임에서 가져옵니다. 일부 도구는 고정된 모델 이름을 제공하고, 일부는 로컬 설정, 로그인 계정, 구독 권한에 따라 사용 가능한 모델을 반환합니다.

### CodeBuddy

Tencent에서 제공합니다. Claude Code 호환 CLI 에이전트입니다 — Multica는 Claude Code와 동일한 stream-json 프로토콜로 구동하므로 세션 재개가 동작하고(`--resume` 경유), MCP 구성은 `--mcp-config`로 전달됩니다. CodeBuddy는 Claude의 디렉터리를 재사용하지 않고 자체 설정 디렉터리를 사용하므로, 스킬은 `.codebuddy/skills/`에 배치되고 런타임 브리핑은 `CODEBUDDY.md`에 기록됩니다. 모델은 동적으로 탐색됩니다.

### 모델 선택 보충

QwenPaw, MiniMax Code, ZeroClaw는 예외입니다. Multica에서 고른 모델을 받아들이지 않으므로 선택 상자가 비활성 상태로 "런타임에서 관리"라고 표시됩니다. 모델은 각 도구의 자체 설정에서 선택하세요. 이 도구들의 모델 목록이 비어 있는 것은 정상이며 런타임이 오프라인이라는 뜻이 아닙니다.

Antigravity의 추론 변형이 `agy models`에 있으면 각각 별도 모델로 표시됩니다. 모델 선택기에서 접미사를 포함해 원하는 변형을 선택하세요. Multica에는 Antigravity의 별도 추론 설정이 없습니다. 사용자 지정 인수로 `--effort`를 전달하면 Antigravity가 선택한 모델과 함께 사용할 수 있는지 검사합니다.

DeepSeek Harness의 모델 카탈로그는 런타임 자체가 제공합니다(`dsh --profile multica --list-models`). 모델 ID는 `provider/model` 형식(예: `deepseek-official/deepseek-chat`)이므로 목록에서 전체 ID를 선택하세요.

<Callout type="info">
모델 이름은 도구끼리 통용되지 않습니다. AI 코딩 도구를 바꾸면 기존 모델 값은 새 도구에서 유효하지 않으므로 다시 선택해야 합니다.
</Callout>

### Codex

표에서 ✓로 표시된 도구는 원래 세션이 남아 있고 그 세션에 접근할 수 있는 런타임이 실행을 처리하면, 이후 실행에서 기존 세션을 이어갈 수 있습니다. MiniMax Code 0.1.2는 ACP에서 세션 로드 기능을 알리지 않으므로 이후 실행에서는 새 MCode 세션을 시작합니다.

Multica는 도구가 반환한 세션 식별자를 저장합니다. 다음에 같은 태스크에서 작업을 이어갈 때 런타임이 이 세션의 복원을 시도합니다. 복원할 수 없으면 새 세션을 만들어 계속 실행합니다. Pi는 로컬 세션 파일 경로를 저장하므로 원래 컴퓨터와 파일에 더 많이 의존합니다.

재시도와 세션 복원 규칙은 [실행](/tasks#수동-재시도)을 참고하세요.

### Cursor

Anysphere에서 제공하며, Cursor 에디터에 대응하는 CLI입니다. **세션 재개가 동작합니다** — 현재 Cursor Agent의 stream-json 이벤트에는 `session_id`가 포함되며, Multica는 다음 실행 때 이를 `--resume <id>`로 다시 전달합니다. MCP 구성은 작업 워크스페이스의 `.cursor/mcp.json`에 기록되고, Cursor의 프로젝트 approval 파일은 작업별 `CURSOR_DATA_DIR` 아래에 기록되므로, 관리되는 MCP 서버는 사용자의 전역 Cursor approval에 의존하지 않습니다.

### Hermes

Nous Research에서 제공합니다. ACP 프로토콜을 사용합니다(Kimi와 전송 계층을 공유합니다). 세션 재개가 동작하고, MCP 구성은 ACP `mcpServers`로 전달됩니다. Hermes는 스킬을 자신의 홈 디렉터리(`~/.hermes/skills/`)와 설정된 `skills.external_dirs`에서만 탐색하며, 워크스페이스 상대 탐색은 하지 않습니다. 그래서 **에이전트에 스킬이 할당된 경우에만** Multica는 `HERMES_HOME`을 사용자 `~/.hermes/`의 작업별 오버레이로 향하게 합니다. 실제 홈은 심링크로 미러되고(auth/시크릿 포함, 토큰 갱신이 전파됨), 파생된 `config.yaml`이 기존 스킬을 읽기 전용 external root로 참조하며, 할당된 스킬만 그 `skills/` 디렉터리에 기록되어 우선합니다. 전역 스킬은 그대로 동작합니다. Multica는 공유 `~/.hermes/`를 직접 수정하지 않고 읽어서 링크만 하지만, Hermes가 미러된 심링크를 통해 쓰는 경우(토큰 갱신 등)는 전파됩니다. `custom_args`의 `-p`/`--profile` 선택은 존중됩니다. 오버레이는 그 profile의 홈에서 시드되고, 플래그는 실행 명령에서 소비되어 오버레이를 우회할 수 없습니다. 작업 메모리는 작업별로 격리됩니다. 새 `memories/` 디렉터리에 더해 파생 설정에서 외부 `memory.provider` 백엔드를 비활성화하므로, 디스크상의 메모도 공유 Supermemory/Hindsight 류의 뱅크도 작업 간에 공유되지 않습니다(관리형 agent 범위 메모리 백엔드는 향후 별도 과제입니다). `state.db` SQLite 세션 저장소와 저널 파일도 작업 로컬이며 Hermes가 오버레이 안에서 생성합니다. 호스트 대화 기록은 링크되거나 복사되지 않고, Windows에서 활성 WAL 잠금이 환경 준비를 막지 않습니다. 스킬이 할당되지 않은 Hermes 작업은 실제 홈 그대로 실행됩니다. 참고로 홈의 플랫폼 기본값은 네이티브 Windows에서 `%LOCALAPPDATA%\hermes`입니다.

**Hermes profile 선택.** 특정 profile로 Hermes를 실행하려면 에이전트의 `custom_args`에 profile 플래그와 profile 이름을 두 개의 독립된 항목으로 설정하세요. 예를 들어 `research`라는 profile을 사용하려면:

```json
["-p", "research"]
```

`"-p research"`처럼 하나의 문자열로 합치지 마세요. Multica는 배열의 각 항목을 하나의 argv 항목으로 도구에 전달합니다. `custom_args`는 에이전트별로 설정합니다 — [에이전트 생성 및 구성](/agents-create)을 참고하세요.

### Kimi

Moonshot에서 제공하며, 중국 시장을 겨냥합니다. Hermes와 ACP 프로토콜을 공유하고 MCP 구성도 ACP `mcpServers`로 전달되지만, 스킬 경로 `.kimi/skills/`는 Kimi CLI의 기본 탐색 메커니즘으로 Hermes의 fallback과는 다릅니다.

### Kiro CLI

Amazon에서 제공합니다. `kiro-cli acp`를 통해 stdio 위에서 ACP를 사용합니다. 세션 재개는 ACP `session/load`로 동작하고, MCP 구성은 ACP `mcpServers`로 전달되며, 모델 선택은 `session/set_model`로 동작하고, 스킬은 프로젝트 수준 기본 탐색을 위해 `.kiro/skills/`로 복사됩니다.

### OpenCode

SST에서 제공하는 오픈소스입니다. 사용 가능한 모델과 모델 variant를 동적으로 탐색합니다(CLI의 구성 파일을 스캔). 세션 재개가 동작하고, 에이전트의 `mcp_config` 필드를 소비합니다. Multica는 `OPENCODE_CONFIG_CONTENT` 환경 변수를 통해 이를 인라인으로 주입하므로, 에이전트의 MCP 서버가 작업 디렉터리의 `opencode.json`(에이전트 또는 사용자가 소유하는 파일)을 건드리지 않고 OpenCode에 전달됩니다. 모델이 variant를 노출하면 Multica는 이를 에이전트 thinking selector로 표시하고 선택한 값을 `opencode run --variant`로 전달합니다. **자신의 모델 카탈로그를 커스터마이징하고 싶은, 만지작거리기 좋아하는 사용자에게 적합합니다.**

### DevEco Code

**DevEco Code**는 Huawei(화웨이)의 HarmonyOS 개발용 독립 코딩 에이전트(`deveco` CLI, [gitcode.com/openharmony-sig/deveco-code](https://gitcode.com/openharmony-sig/deveco-code))입니다. OpenCode 엔진을 기반으로 하면서도 자체적으로 완성된 성숙한 제품으로, 자체 모델 카탈로그와 provider(내장 `deveco/GLM-5.1`), Huawei 계정 인증, 전용 설정·스킬 체계(`~/.config/deveco/` 및 `.deveco/skills/`)를 갖추고 있습니다. Multica는 `deveco run --format json`으로 구동하며 NDJSON 이벤트 스트림을 파싱합니다. **세션 재개가 동작합니다**(`--session <id>` 경유). 모델은 `deveco models`에서 동적으로 탐색되고, 시스템 컨텍스트는 작업별 `AGENTS.md`로 전달됩니다. MCP 서버는 DevEco 네이티브 `DEVECO_CONFIG_CONTENT` 채널로 설정합니다. Multica 측 `mcp_config` 연동은 개발 중이며, 현재 DevEco 에이전트의 MCP 탭은 숨겨집니다. 인증은 `deveco auth login`(Huawei 계정)으로 수행합니다.

### OpenClaw

오픈소스 프로젝트이며, CLI 에이전트 오케스트레이터입니다. MCP 구성은 Multica의 작업별 config wrapper를 통해 기록됩니다. **모델이 에이전트 계층에 바인딩됩니다**(`openclaw agents add --model`) — 작업마다 재정의할 수 없습니다. 구성이 엄격하게 통제됩니다: 사용자는 `--model`이나 `--system-prompt`를 전달할 수 없으며, 에이전트 등록 구성이 결정합니다.

### Pi

Inflection AI에서 제공하며, 미니멀합니다. **세션 재개 방식이 특이합니다** — 세션 ID가 문자열 ID가 아니라 디스크상의 파일 경로(`~/.pi/...`)입니다. 다른 도구에서는 재개 id가 CLI가 반환하는 문자열이지만, Pi에서는 재개 id가 세션 파일 그 자체입니다.

### OMP

[Oh My Pi](https://omp.sh)는 독립적인 코딩 에이전트이며, **Pi의 별칭이 아닙니다**. Multica는 `omp -p --mode json --session-dir <dir>`를 비대화형으로 실행하고 Pi 호환 JSON 이벤트 스트림을 읽습니다. 이벤트가 반환하는 문자열 session ID는 다음 작업에서 `--resume <id>`로 전달되어 세션을 재개합니다. 모델과 지원되는 thinking level은 `omp models --no-extensions --json`에서 동적으로 탐색되며, 선택된 model selector는 `--model`, thinking level은 `--thinking`으로 전달됩니다. 할당된 워크스페이스 스킬은 OMP의 네이티브 탐색을 위해 `.omp/skills/`에 기록됩니다.

OMP를 활성화하려면 먼저 OMP를 설치하고 인증한 뒤 daemon의 `PATH`에서 `omp`를 찾을 수 있게 하거나, `MULTICA_OMP_PATH`에 절대 실행 경로를 설정하세요. daemon을 다시 시작하거나 새로 고쳐 런타임을 재탐색합니다. OMP selector를 `MULTICA_OMP_MODEL`로 설정하면 daemon 전체의 기본 모델이 되고, 개별 에이전트에서는 동적으로 발견된 selector를 선택할 수 있습니다. OMP는 현재 에이전트의 `mcp_config`를 무시합니다.

### Qoder

Alibaba에서 제공합니다. 에이전트형 코딩 CLI입니다. stdio 위에서 ACP 프로토콜을 사용합니다(Hermes, Kimi, Kiro CLI와 전송 계층을 공유합니다). 세션 재개는 ACP `session/resume`를 통해 동작하고, MCP 구성은 ACP `mcpServers`로 전달되며, 모델 선택은 동적으로 탐색되고, 스킬은 네이티브 탐색을 위해 `.qoder/skills/`로 복사됩니다.

### Trae

ByteDance의 공식 TRAE CLI(`traecli`, Trae IDE와 함께 쓰는 제품이며 오픈소스 `bytedance/trae-agent`가 아닙니다)입니다. ACP 네이티브라서 Multica는 `traecli acp serve --yolo`로 stdio 위에서 구동하며, Kiro 및 Qoder와 같은 전송 계층을 사용합니다. 세션 재개는 ACP `session/load`로 동작하고, MCP 구성은 ACP `mcpServers`로 전달되며, 모델은 동적으로 탐색되어 작업별로 `session/set_model`로 전환됩니다. 스킬은 `.traecli/skills/`로 복사됩니다.

### Grok

xAI의 Grok Build CLI(`grok`)입니다. Multica는 `grok --no-auto-update agent --always-approve stdio`로 ACP에 연결합니다. `initialize` 응답 후 CLI가 광고한 방식 중 `xai.api_key`(`XAI_API_KEY`가 설정된 경우 우선) 또는 `cached_token`을 선택하고, `authenticate`가 성공한 뒤에만 세션을 만들거나 불러옵니다. 사용할 수 있는 방식이 없으면 명시적으로 실패합니다. 세션 재개는 ACP `session/load`, 모델은 `session/new`에서 동적으로 탐색하고 `session/set_model`로 전환합니다. `grok-4.5`의 reasoning effort는 공식 지원 값인 `low`, `medium`, `high`만 제공합니다. MCP 구성은 ACP `mcpServers`로 전달됩니다. 스킬은 `.grok/skills/`에 기록되며, 사용자 스킬은 `$GROK_HOME/skills/`(기본값 `~/.grok/skills/`)과 공용 `~/.agents/skills/`에서 탐색됩니다.


### MiniMax Code

MiniMax 제공 ACP 네이티브 코딩 에이전트(`mcode` CLI)입니다. MCP 구성은 ACP `mcpServers`로 전달되고, 스킬은 `.minimax/skills/`에 기록되어 네이티브로 발견됩니다. 모델 선택은 런타임에서 관리하므로 선택 상자는 비활성 상태로 "런타임에서 관리"라고 표시됩니다. MiniMax Code 0.1.2는 ACP에서 세션 로드 기능을 알리지 않으므로 이후 실행에서는 새 MCode 세션을 시작합니다.

## 세션 재개: 실제로 지원하는 도구

세션 재개 메커니즘은 [작업](/tasks#수동-재시도)에서 다룹니다. **지원되는 모든 도구가 세션을 재개합니다** — 재개 id를 전달하면 작업이 이전 컨텍스트에서 이어집니다. 유일한 예외는 Pi로, 재개 id가 문자열 ID가 아니라 디스크상의 세션 파일 경로입니다(위의 [Pi](#pi) 참고).

## MCP 구성: 도구별 지원

**31개 도구 중 `mcp_config`를 실제로 사용하는 도구는 22개입니다: CodeArts, Claude Code, CodeBuddy, Codex, Cursor Agent, DeepSeek Harness, Devin, Dim, Grok, Hermes, Kimi CLI, Kiro CLI, MiniMax Code, OpenClaw, OpenCode, Pi, Qoder CLI, Qoder CN CLI, Qwen Code, Reasonix, Trae CLI, ZCode**. 나머지 9개(Amp, Antigravity, GitHub Copilot CLI, DevEco Code, Factory Droid, Muse Code, OMP, QwenPaw, ZeroClaw)는 에이전트 MCP 구성을 읽지 않으므로 설정해도 효과가 없습니다.

각 도구의 연결 방식은 다릅니다: Claude Code와 CodeBuddy는 `--mcp-config`와 `--strict-mcp-config`로 받고, Codex는 데몬이 관리하는 `mcp_servers` 블록을 작업별 `$CODEX_HOME/config.toml`에 기록하며, Cursor는 `.cursor/mcp.json`과 작업별 `CURSOR_DATA_DIR` 아래의 프로젝트 approval을 기록합니다. Hermes/Kimi/Kiro CLI/Qoder/Trae CLI/Grok은 ACP `mcpServers`로 받습니다. OpenCode는 `OPENCODE_CONFIG_CONTENT` 환경 변수로 인라인 구성을 받고, OpenClaw는 Multica의 작업별 config wrapper를 통해 `mcp.servers`를 받습니다. OpenCode 경로는 프로젝트의 `opencode.json`을 다시 쓰지 않습니다.
Amp, Factory Droid, Antigravity, GitHub Copilot CLI, DevEco Code, Muse Code, ZeroClaw는 현재 에이전트의 MCP 설정을 읽지 않으므로 에이전트를 만들 때 이 항목이 표시되지 않습니다.

Pi에 관리형 MCP 설정을 전달하려면 Pi 0.99.0 이상이 필요합니다. 이전 Pi 버전에서도 MCP 설정이 없는 에이전트는 계속 실행할 수 있습니다.

<Callout type="warning">
MCP server의 명령, 인수, 환경 변수는 에이전트 설정과 함께 서버에 저장됩니다. 공유할 필요가 없는 로컬 자격 증명을 설정에 직접 넣지 마세요.
</Callout>

<Callout type="warning">
에이전트 구성에서 `mcp_config`를 설정했더라도 MCP 열에 ✅가 없는 도구를 선택하면, MCP 서버가 해당 에이전트에 **아무런 효과**도 미치지 않습니다. MCP 연동은 도구별로 구현됩니다.
</Callout>
런타임 컴퓨터에 이미 설정된 MCP server는 그 컴퓨터에서 에이전트 설정과 합쳐집니다. [로컬 MCP 설정](/daemon-runtimes#local-mcp)을 참고하세요.


## 스킬 주입 방식

각 도구는 **자체** 스킬 탐색 경로를 사용합니다. 작업이 실행되기 전에 Multica 데몬이 워크스페이스의 스킬 파일을 해당 경로로 복사합니다:

저장소에 원래 있던 스킬은 덮어쓰지 않습니다. 이름이 충돌하면 Multica가 주입하는 복사본에 다른 디렉터리 이름을 사용하며 실행이 끝나면 자신이 만든 파일만 정리합니다.

| Grok | `.grok/skills/` | ✅ 네이티브 |
| MiniMax Code | `.minimax/skills/` | ✅ 네이티브 |
| Antigravity | `.agents/skills/` | ✅ 기본 (Gemini CLI의 워크스페이스 레이아웃을 따름 — [Antigravity 문서](https://antigravity.google/docs/gcli-migration) 참고) |
| Hermes | `HERMES_HOME/skills/` (작업별 홈) | ✅ 기본 (작업별로 `~/.hermes/`에서 시드) |
| OpenClaw | `.agent_context/skills/` | ⚠️ 범용 fallback |

fallback 경로를 쓰는 도구가 실제로 이 디렉터리를 읽는지는 해당 도구 자체의 문서에 따라 달라지며 — 보장되지 않습니다. OpenClaw에서 스킬이 적용되지 않는다면, 먼저 이 점을 확인하세요.

- Codex는 실행별 `CODEX_HOME`을 사용하며 시스템 수준 Codex 디렉터리에 스킬을 기록하지 않습니다.
- Hermes는 실행별 `HERMES_HOME`을 사용합니다. 기존 로컬 설정은 계속 읽을 수 있지만 연결된 스킬과 세션 데이터는 실행별로 격리됩니다. 이 격리는 에이전트에 스킬이 연결된 경우에만 사용되며, 연결된 스킬이 없는 실행은 컴퓨터의 기존 Hermes 홈 디렉터리를 사용합니다.
- OpenClaw는 현재 실행용 작업 디렉터리의 `skills/`를 사용하고 실행별 설정을 통해 이 디렉터리를 워크스페이스로 지정합니다.

스킬의 생성과 사용은 [스킬](/skills)을 참고하세요.

## ZCode

ZCode는 네이티브 NDJSON `app-server` 프로토콜로 세션 생성·재개·취소, 모델 검색, 추론 수준, MCP를 지원합니다. 태스크는 yolo 모드로 실행되며 대화형 도구 승인을 기다리지 않습니다. 추론 수준 선택지는 런타임 모델 카탈로그에서 가져오고, 에이전트 생성 시 선택한 모델의 기본값을 유지합니다.

macOS에서는 ZCode Desktop에 포함된 CLI도 자동으로 감지합니다. Node.js가 설치되어 있어야 합니다. Linux에서도 ZCode Desktop을 자동으로 감지하고 데스크톱 창을 열지 않고 내장 CLI를 실행합니다. Node.js를 별도로 설치하거나 환경 변수를 직접 설정할 필요가 없습니다. 데스크톱 앱에서 활성화한 API-key/Coding Plan 연결을 프로세스 전용 임시 설정으로 가져옵니다. 이 설정은 종료 시 삭제되며 원본 파일은 변경하지 않습니다. Start Plan 인증 토큰은 API 키가 아니므로 이 계정 인증 방식은 지원하지 않습니다. 모델이 검색되지 않으면 ZCode Desktop에서 작동하는 API 연결을 설정하세요.
